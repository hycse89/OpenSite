0. Executive Summary

문제의식
  • 구조적 불일치: 산업 변화 속도(월 단위) vs 교육 제도 속도(년 단위).
  • 기존 한계: 대학은 지식 축적 최적화로 대응이 느림.
  • 상업 위험: 단기 성과 경쟁 비용을 학생이 떠안음.
핵심 정의

PSS → ADS → DX → AX

  • AX를 유행어가 아닌 인간-시스템 관계의 장기 연구로 정의.
  • 특정 도구에 종속되지 않는 철학과 구조 유지.
해결책: 교육이 아닌 환경 설계
1. 실전 환경: Chat/API, LLM/SLM 전제
2. 규칙 기반: 예외 없는 기준과 재현성
3. 자동 선별: 선택에 따른 결과(탈락/승격)
4. 지속 성장: 장기 지식 인프라 제공

"빠르되, 소모하지 않는다. 교육이 아니라 환경을 제공한다."

1. 문제 정의: 구조적 불일치

1.1 수요 폭발

AX 인력 ≠ 단순 AI 기술자

  • AI를 업무 파트너로 인식
  • 문제를 AI 친화적으로 재정의
  • 비용/리스크 고려한 설계 능력
1.2 속도 괴리
  • 산업: 월 단위 변화 (모델 급변)
  • 교육: 학위/학기 단위 (검증 중심)

*교육이 느린 건 실패가 아니라 설계 목적이 다르기 때문.

1.3 대학의 한계
  • 형식(학점/논문) 중심 평가
  • 최신 도구/API 환경 제공 난항
  • 명확한 역할 분리(AX는 융합 요구)
1.4 ~ 1.6 제3의 경로 필요성
구분 대학 모델 상업 교육 PSSLAB 모델
속도 느림 (검증) 빠름 (결과) 빠름 (실험)
리스크 낮음 학생에게 전가 구조가 흡수
방식 지식 전달 스킬 주입 환경/규칙 제공

2.1 PSS: 가치란 무엇인가
  • 고대 성수 판매기 사례: 제품+서비스+경험의 결합.
  • 가치는 물건이 아닌 행위와 맥락 속에서 생성됨.
  • 이분법(HW/SW)은 가치 생성 메커니즘 설명 불가.
2.3 ADS: 구조적 관점
  • Analog: 인간, 감각, 직관, 현장, 암묵지
  • Digital: 데이터, 규칙, 알고리즘, 명시지
  • 이 둘의 긴장과 결합이 핵심.
2.6 AX의 필연성: 인간의 귀환

"AX는 DX로 확장된 Digital 시스템을 다시 인간 경험(Analog)으로 재통합하는 국면이다."

  • AI는 도구가 아니라, 인간 판단을 증폭시키는 행위자.
  • AX는 교육 문제가 아니라 관계 설계/구조 문제.

3. PSS → ADS → DX → AX 계보

3.1 계보의 중요성
  • AX를 "DX 다음 단계"나 "단순 유행"으로 보면 실패함.
  • 하나의 사상적/구조적 계보의 최신 국면으로 이해해야 함.
  • 기술 트렌드와 구조적 사고를 분리하는 기준점.
3.7 기술 진보가 아닌 역할 재설계

"무엇을 자동화할 것인가" (X)
"무엇을 인간이 계속할 것인가" (O)

  • 기술 선택보다 역할 설계가 핵심.
  • 개발자/경영자만의 영역이 아닌 관계의 문제.
3.8 인력 형성으로의 연결:
AX 인력은 새로운 기술자가 아니라, 인간-AI 관계를 설계할 수 있는 사람이다. 이는 교과목 추가가 아닌, 구조 속에서의 실험으로만 길러진다.

5. 단계별 구조 (Levels)

단계는 성취(Achievement)가 아니라 책임(Responsibility)의 범위입니다.

⚪ 수료 (Completion)
"아는 사람" / 관찰자
  • 목표: AX 환경 이해, 부적합 조기 인식.
  • 제공: 최소 공통 환경, 성과 요구 없음.
🟤 브론즈 (Bronze)
"쓸 수 있는 사람" / 실무자 (생존선)
  • 목표: 어디 가도 1인분 하는 최소 AX 실무자.
  • 필수: AI 사용(Chat/API) + CS 기초(3학년 수준).
  • 특징: 수학/영어 강요 안 함 (안 하면 못 올라감).
⚪ 실버 (Silver)
"설계하는 사람" / 전문가 (석사급)
  • 목표: 자기주도 문제 정의, 재현 가능한 결과.
  • 특징: 정답 없음. 영어 발표/자료 도입(글로벌 적응).
🟡 골드/블랙 (Gold/Black)
"만드는 사람" / 공동 창작자
  • 목표: 방법론 개선, 구조 설계 참여.
  • 기준: 시험(X) → 기여(O) 기반 승급.

6. 평가·탈락·재진입

6.1 & 6.2 평가의 본질과 자동 탈락
  • 평가는 "누가 남아야 하는가"가 아닌 "누가 책임을 질 수 있는가" 확인.
  • 자동 탈락: 미제출, 기준 미달 시 예외 없음. (정치/감정 배제)
  • 탈락은 실패가 아니라 '구조적 부적합' 확인 과정.
6.3 핵심 평가 기준
  1. 문제 정의: AX 관점에서 의미가 있는가?
  2. 설계 정당성: 모델/API 선택 이유가 있는가?
  3. 설명 가능성: 결과를 사람이 이해 가능한가?
  4. 재현 가능성: 로그/설정이 남아 있는가?
6.4 비용을 평가 도구로 전환

비용 = 설계 능력의 지표

  • 무분별한 토큰 사용 = 감점 (설계 부족).
  • 비용 절감을 위한 구조적 시도(캐싱, 프롬프트 최적화) = 가점.
6.6 재진입 메커니즘
기회 중심 설계: 일정 기간 후 재진입 허용. 이는 구제가 아니라 책임의 재선택.

7. AI 사용 구조와 비용

"비용은 돈의 문제가 아니라 구조 통제의 문제다."
7.3 중앙 게이트웨이 모델
  • 방식: 개인 결제/Key 금지. 중앙 관리형 계정 사용.
  • 장점: 공정성 확보(빈부격차 배제), 비용 예측 가능.
  • 기능: 사용량/모델/목적 로그 전수 수집 → 평가 활용.
7.4 4대 환경 동시 제공

초기부터 아래 4가지를 모두 제공하여 설계 능력 배양

  • Chat LLM
  • Chat SLM
  • API LLM
  • API SLM
7.6 접근성 평준화
  • 클라우드 기반 접근 기본 (개인 PC 성능 격차 해소).
  • SLM 활용을 통한 비용/구조 최적화 훈련.

8.3 AI의 역할
  • 과제: 단계별 자동 생성 및 난이도 조정.
  • 평가: 형식 요건, 설명 구조, 로그 분석 (1차 필터).
  • 로그: 감시가 아닌 사고의 흔적 분석.
8.5 감정 노동 제거
  • 탈락/피드백을 규칙 기반 시스템이 수행.
  • 개인적 거절이 아닌 '구조적 결과'로 인식 유도.
  • 운영자의 피로도 감소 및 지속성 확보.

9. 비독점적 전수와 재현

9.1 확대(Scale-up) vs 재현(Reproduction)
  • 확대 지양: 중앙 독점, 종속성, 리스크 증가.
  • 재현 지향: 동일 구조/원칙이 각자 맥락에서 자율 작동.
  • 목표: 창시자 없이도 돌아가는 시스템.
9.3 파일럿 실험의 의미
  • 사람을 시험하는 것이 아님.
  • 구조를 검증하고 운영 데이터를 축적.
  • 실패 사례까지 전수 가능한 지식으로 정리.
9.4 지속적 기여 (통제 없는 연결)

비독점적 전수가 "단절"을 의미하지 않음.

  • 방법론 업데이트, 컨텐츠 보완 등 기여는 지속.
  • 단, 중앙이 운영 권한을 독점하거나 통제하지 않음.

10. 컨텐츠 전략

"컨텐츠는 정답집이 아니라, 사고와 실험이 반복된 흔적(성장 인프라)이다."
10.3 구성 요소
  1. 방법론 세트: 문제 정의 프레임, 역할 분해.
  2. 실패 기록: 성공보다 중요한 '왜 안 되었는가'.
  3. 기술 MVP: 완성품이 아닌 사고의 출발점.
  4. 철학 문서: PSS/ADS/AX 연결 고리.
10.4 단계별 접근
  • 수료/브론즈: 개념, 방향성, 제한된 사례 (보호).
  • 실버: 전체 방법론, 작업 도구화.
  • 골드/블랙: 수정/추가 권한, 공동 창작.
10.5 컨텐츠와 사람의 관계
컨텐츠는 락인(Lock-in) 수단이 아님.
떠나서도 성장할 수 있게 하는 도구이며, 사고 프레임은 개인에게 남는다.

12. 이 모델이 지향하지 않는 것

윤리적·구조적 안전장치를 위한 부정(Not)의 선언

학생을 수단화하지 않는다
  • 마케팅용 성공 사례로 소비 금지.
  • 숫자 경쟁(취업률 등) 지양.
  • 학생은 증거가 아닌 경험 주체.
개인/조직 영속이 목표가 아니다
  • 창시자 중심 서사 거부.
  • 대규모 조직 확대 지양.
  • 사람이 사라져도 구조는 남아야 한다.
정답과 안전을 제공하지 않는다
  • 성공 보장, 취업 보장 없음.
  • 불확실성을 제거하는 대신 다루는 법을 훈련.
정치적 구조 배제
  • 추천, 연줄, 특혜 없음.
  • 예외 없는 규칙 적용으로 신뢰 유지.
