제2장. Attention: 맥락(Context) 인식의 메커니즘

: 압축을 넘어, 언제든 다시 참조하다

제2장은 AI 모델이 인간의 언어를 처리하는 방식에서 가장 극적인 변화가 일어난 지점입니다. 기존 RNN 기반 모델들이 긴 문장을 하나의 고정된 벡터에 억지로 '압축(Compression)'하려다 실패했던 반면, Attention은 필요할 때마다 원문을 다시 '검색(Retrieval) 및 참조'하는 방식으로 패러다임을 완전히 뒤집었습니다.

2.1. 병목의 발견: 고정 길이 벡터의 한계

2.1.1. Seq2Seq 모델의 표준 구조

기존의 인코더-디코더(Seq2Seq) 구조는 인코더가 입력 문장의 모든 정보를 처리한 후, 마지막 시점의 은닉 상태(Context Vector) 하나만을 디코더에게 넘겨주는 방식이었습니다.

2.1.2. 정보 병목 현상 (Information Bottleneck)

문제는 이 컨텍스트 벡터가 고정된 크기(Fixed-size)를 가진다는 점입니다. "Hello"라는 짧은 인사말이든, 긴 연설문이든 동일한 크기의 벡터(예: 512차원)에 욱여넣어야 했습니다. 이로 인해 긴 문장의 앞부분 정보가 소실되거나, 복잡한 뉘앙스가 뭉개지는 현상이 발생했습니다.

2.2. Attention의 핵심 원리: Query, Key, Value (Q, K, V)

2.2.1. 발상의 전환: "다 가지고 있자"

Attention 모델은 인코더가 생성한 모든 시점의 은닉 상태들(\(h_1, h_2, ..., h_n\))을 버리지 않고 '기억 은행'에 보관합니다. 디코더는 단어를 생성할 때마다 이 은행을 열람합니다.

2.2.2. 3대 요소: Q, K, V

정보 검색 시스템에서 차용한 개념을 사용합니다.

  • Query (\(Q\)): "지금 내가 무엇을 궁금해하는가?" (디코더의 현재 상태)
  • Key (\(K\)): "정보를 찾기 위한 꼬리표는 무엇인가?" (인코더의 각 단어들의 은닉 상태)
  • Value (\(V\)): "실제 내용은 무엇인가?" (인코더의 각 단어들의 실제 값)
💡 비유: 도서관에서 책 찾기

Query: "인공지능의 역사에 대한 책 찾아줘." (나의 요청)
Key: 도서관 책들에 붙어 있는 라벨 (책 제목)
Value: 실제 책의 내용

내 요청(Query)과 책 제목(Key)을 대조(Matching)하여 가장 관련 있는 책의 내용(Value)을 읽습니다.

2.3. 유사도 계산과 정렬 (Alignment & Softmax)

2.3.1. 1단계: 유사도 계산 (Score Calculation)

디코더의 현재 상태(Q)가 인코더의 각 기억(K)과 얼마나 관련이 깊은지 내적(Dot Product)을 통해 계산합니다. 벡터의 방향이 비슷할수록 내적 값이 큽니다.

\[ Score = Q \cdot K^T \]

2.3.2. 2단계: 확률 변환 (Softmax)

계산된 점수들을 Softmax 함수에 통과시켜 총합이 1인 확률값(Attention Weight)으로 변환합니다. 이를 통해 모델은 어디에 집중(Focus)할지 결정합니다.

  • 예: "I(0.05), love(0.85), you(0.10)" → 'love'에 85% 집중

2.3.3. 3단계: 가중합 (Weighted Sum)

계산된 확률을 실제 정보(V)에 곱해서 더합니다. 이렇게 만들어진 동적 컨텍스트 벡터(Context Vector)는 현재 시점에 딱 필요한 정보만 추출한 결과물입니다.

2.4. Global Dependency: 거리를 지우다

2.4.1. 거리의 폭정에서 해방

Attention 메커니즘의 가장 큰 기술적 성취는 물리적 거리의 개념을 없앤 것입니다.

특성 RNN / LSTM Attention
연결 구조 사슬형 (Chain) 완전 연결형 (Fully Connected)
신호 경로 길이 \(O(n)\) (거리에 비례) \(O(1)\) (상수, 거리 무관)
장기 기억력 약함 (거리가 멀수록 희석됨) 강함 (거리에 상관없이 즉시 참조)

이로써 모델은 문장의 맨 처음 단어와 맨 끝 단어를 단 한 번의 연산으로 연결할 수 있게 되었습니다. 이는 제3장에서 다룰 Transformer가 RNN을 완전히 버리게 되는 결정적인 근거가 됩니다.
